# Dock persistent media controls compactly instead of overlaying content

Ongoing-activity controls (e.g. playback of a read-aloud) should be compact and docked into an existing chrome region such as a footer, not float over content where they obscure it.

## Why

Floating controls hide the content the user is reading or listening to; a compact docked control keeps state visible without competing with content.

## Prefer

- Narrow, icon-led controls docked into an existing footer or bar
- Icon replacing text labels where the icon is recognizable

## Avoid

- Wide floating popups that cover messages
- Text-heavy control bars

## Use when

- A background activity (audio playback, long-running process) needs persistent controls while the user keeps reading.

## Do not use when

- The control is a modal decision the user must address immediately.

## Evidence

- User asked to shrink a floating read-aloud control and move it into the settings footer so it would not obscure anything.

## Check

- Does the persistent control cover any content at common viewport sizes?
- Is its width the minimum needed for its actions?
