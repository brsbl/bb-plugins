# Make workspace separation visible in local navigation

When bb presents Plugins and Skills as separate workspaces, scope each workspace's sidebar and top navigation to its own pages so the interface expresses that separation.

## Why

Separate entry labels do not establish separate workspaces if both destinations still expose the same combined navigation.

## Prefer

- Plugins navigation containing plugin pages and Skills navigation containing skill pages.
- Local navigation that reflects the workspace the user entered.

## Avoid

- Renaming entry points while retaining a combined Extensions workspace in the visible navigation.

## Use when

- Separating Plugins and Skills into distinct bb workspaces.

## Do not use when

- Designing an intentionally unified resource workspace or global application navigation.

## Evidence

- Rejected separate Plugins and Skills labels while both retained the same sidebar and top navigation; requested pages scoped to each workspace.

## Check

- Does each workspace expose only its own resource pages in local navigation?
- Do the sidebar and top navigation express the same workspace identity?
