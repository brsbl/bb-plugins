# Encode the takeaway so it visibly comes across

When a data visualization is meant to show a specific insight, encode it in a channel viewers can actually perceive at playback speed (e.g. thickness, relative speed), and slow the animation enough for it to register; an encoding nobody notices doesn't count.

## Why

A subtle encoding (tail length on fast-moving trains) failed to communicate speed; the visualization should make the claimed takeaway obvious.

## Prefer

- salient channels like thickness or true relative motion speed
- slower pacing so changes are readable
- stills that clearly demonstrate each claimed fact

## Avoid

- claiming the visual shows something only an explanation reveals
- animation too fast to read the encoded variable

## Use when

- pairing data visualizations with stated takeaways or captions

## Do not use when

- purely decorative or ambient motion

## Evidence

- User said a speed encoding via tail length 'did not come across' and asked for thickness, slower playback, and true relative train speeds.

## Check

- Could a first-time viewer name the takeaway from the visual alone?
- Is playback slow enough to perceive the encoded variable?
