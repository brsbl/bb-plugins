# Make the palette useful before it has usage history

The command palette's initial view should provide useful available actions or content without requiring prior palette use.

## Why

A user should be able to discover value on the first open instead of having to establish a history before the starting view becomes useful.

## Prefer

- Useful available actions or existing content before typing, even for someone who has never used the palette.
- Empty-state copy that describes actual absence of content rather than absence of palette history.

## Avoid

- Making recent palette usage the prerequisite for useful initial content.

## Use when

- Designing the before-typing or first-use state of the command palette.

## Do not use when

- Designing an explicitly labeled history view whose purpose is to show previous usage.

## Exceptions

- History may personalize results as long as users without history retain a useful starting view.

## Evidence

- While discussing palette defaults, the user explicitly required an empty or starting state that did not depend on people having used the palette.

## Check

- Does a user with no palette history still see useful available actions or content?
- Does the interface distinguish missing history from genuinely missing content?
