# Keep unavailable actions visible and say why

When an action cannot run right now, keep it in place, disabled, with its reason stated, rather than hiding it or restructuring the surface around its absence.

## Why

Hiding an action removes the user's knowledge that the capability exists and breaks a control layout they navigate by memory; a stated reason turns a dead control into a next step.

## Prefer

- Keep the control in its usual position, visibly disabled.
- State the reason in a tooltip, helper text, or adjacent copy, and the action that would enable it.

## Avoid

- Hiding or removing an action because it is temporarily unavailable.
- A disabled control with no explanation.
- Collapsing a menu or toolbar the user knows because it currently has nothing to run.

## Use when

- A specific action exists but is blocked by state, permission, or a missing prerequisite.

## Do not use when

- The container has no content at all; ddr_005 decides whether it should remain.
- The user can never perform the action in this context, so showing it adds only noise.

## Evidence

- Hid empty content sections while keeping a blocked action visible and disabled with its reason stated.
- Reversed a decision to collapse a menu when empty, keeping the control present and disabled.

## Check

- Is the unavailable action still visible where the user expects it?
- Does it read as disabled, and is the reason and the way to enable it stated?
- Is the disabled state reachable and explained for keyboard and screen-reader users?
