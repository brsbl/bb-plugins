# Preserve the image being viewed through timeline changes

If an eligible image is already open in a lightbox, a later timeline change that makes it ineligible should not remove the displayed image or dismiss the lightbox. Apply this retention only to the image currently being viewed.

## Why

Background timeline changes should not interrupt the user's ongoing inspection of an image.

## Prefer

- Keeping the currently displayed image stable until the user leaves it.
- Applying current eligibility to all other navigation entries.

## Avoid

- Closing the lightbox or removing the displayed image because its timeline source becomes ineligible.
- Retaining ineligible neighboring images merely because they were navigable.

## Use when

- An open bb timeline lightbox updates as timeline content or expansion state changes.

## Do not use when

- Deciding whether an ineligible image may initially open.
- Retaining images that are merely reachable through navigation.

## Evidence

- In live lightbox feedback, the user explicitly rejected removing an open image after eligibility changes and limited retention to the current image.

## Check

- Does the displayed image remain open when its timeline source becomes ineligible?
- Do other ineligible images leave navigation?
- Is retention limited to the current image?
