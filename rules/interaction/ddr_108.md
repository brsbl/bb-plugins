# Keep cached content readable through slow or failed refreshes

For bb read-only pages and thread timelines with cached content, display that content immediately, fetch newer data in the background, and update the visible content only after a successful response. A slow or failed refresh should preserve the readable cached view.

## Why

A slow connection should not prevent someone from reading content already available to the app.

## Prefer

- Immediately render available cached content while requesting newer data in the background.
- Retain readable content when a background request fails.

## Avoid

- Replacing available cached messages with a blocking loading skeleton.
- Discarding the current readable page because a refresh fails.

## Use when

- Designing loading and refresh behavior for bb read-only pages or thread timelines with available cached content.

## Do not use when

- No cached content is available.
- Designing mutation confirmation or write behavior.

## Evidence

- During a poor-network loading discussion, the user asked for cached messages immediately, background refresh, and visible updates only after successful requests.

## Check

- With cached content and a delayed refresh, does the content appear immediately?
- If the refresh fails, does the cached content remain readable?
- Does a successful refresh update the displayed content?
