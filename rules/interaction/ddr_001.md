# Keep routine utilities compact, with exact icons

Routine inspection and operational utilities default to compact icon-only controls with concise tooltips and accessible names. Replace text with an icon only when the symbol is semantically exact, keep any count or state that changes a decision, and reserve labeled buttons for primary workflow transitions.

## Why

This reduces label noise in dense operational surfaces while preserving discoverability and a clear primary-action hierarchy. Compactness helps only when users can still understand the object, state, or action without guessing.

## Prefer

- Use a semantically exact, canonical icon with an accessible name and concise tooltip.
- Keep counts or state beside the icon when they change the user's decision.
- Use a labeled button for the one action that advances the primary workflow.

## Avoid

- Large labeled controls for refresh, retry, view output, open source, or similar inspection utilities.
- Icon-only treatment for unfamiliar, destructive, or primary actions.
- Ambiguous icons that erase essential state or quantity.
- Decorative emoji in product chrome.

## Use when

- The action is routine, local, reversible, and repeatedly used in a dense surface.
- Text is being replaced with an icon to reduce density.

## Do not use when

- The action is unfamiliar, destructive, or the primary transition.
- The icon cannot express the action or concept precisely.

## Exceptions

- **The action is primary, destructive, unfamiliar, or difficult to represent precisely.** Use a concise labeled control and the appropriate confirmation or recovery treatment. Clarity and safety outrank density.

## Evidence

- Requested a compact comment popover with inline counts and no carets.
- Requested semantic attachment and chat icons retain necessary counts, while row borders become lighter.
- Rejected a decorative emoji in product chrome.

## Check

- Are routine utilities compact without competing with the primary action?
- Is each icon semantically exact, and does removing text hide quantity or state?
- Does every icon-only action have an accessible name and concise tooltip?
- Would a first-time user understand any action that remains unlabeled?
