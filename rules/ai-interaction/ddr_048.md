# Keep thread titles anchored to the core job

Keep BB thread titles succinct and stable around the thread's core job; rename when that job changes, rather than to describe each turn's subtask.

## Why

Frequent, granular renaming makes threads harder to recognize and causes the user to lose context.

## Prefer

- Succinct titles describing the enduring core job
- Retaining a recognizable title across implementation subtasks

## Avoid

- Renaming around the latest turn
- Frequent title churn as work progresses

## Use when

- Automatically naming or reassessing BB thread titles

## Do not use when

- The user explicitly requests a particular title

## Exceptions

- Rename when the thread's actual core job changes.

## Evidence

- The user reported losing thread context from frequent granular renaming and asked for succinct titles carrying the core job rather than the last turn's task.

## Check

- Does the title describe the thread's core job?
- Would the title remain recognizable across routine subtasks?
