# Deliver Moss notes through the normal workspace

For a Moss note request, create the note in the default Moss workspace and return a link for the user to open in the production app. Do not launch a Moss development build as part of note authoring. Retired: a process instruction from the user's agent guidelines, not a design preference.

## Why

A note request should end with an accessible note in the normal workspace without requiring a development-app session.

## Prefer

- Create the note in the default Moss workspace.
- Return a clickable note link so the user controls opening it in the production app.

## Avoid

- Launching Moss development builds to create or present personal notes.

## Use when

- An agent is asked to create or deliver a Moss note.

## Do not use when

- The task is testing product code changes in the Moss repository.

## Exceptions

- Development builds are appropriate when testing changes to the Moss repository.

## Evidence

- The user rejected recurring development-app launches for note requests and required default-workspace notes with production-app links.

## Check

- Is the note saved in the default workspace?
- Does the handoff provide a clickable note link?
- Did note authoring avoid launching a development build?
