# Tab controls should sit below titles in the visual hierarchy

In bb tab headers, style navigation arrows, close, and add controls one or two visual steps below tab titles so they read as supporting controls.

## Why

Tab names identify the content; equally prominent utility glyphs compete with that information.

## Prefer

- Make tab titles the dominant element.
- Use quieter glyph styling for arrows, close, and add actions.

## Avoid

- Giving utility glyphs the same visual emphasis as tab titles.

## Use when

- Styling bb tab headers with navigation, close, or add controls.

## Do not use when

- Designing a toolbar whose actions are the primary content.

## Exceptions

- Preserve accessible contrast and usable interaction targets when reducing visual emphasis.

## Evidence

- During a tab-header redesign, the user asked for arrows, close, and add glyphs to sit one or two visual steps below titles.

## Check

- Do tab titles read first, with arrows, close, and add recognizable as supporting controls?
