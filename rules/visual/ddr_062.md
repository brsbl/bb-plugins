# Use meaningful visual representations in plugin surfaces

Prefer visual representations that show the relationships users need to understand in bb plugins, with enough explanation to make their meaning clear.

## Why

The user explicitly identifies as a visual learner and wants plugin surfaces to show information rather than rely on prose.

## Prefer

- Spatial representations for spatial relationships.
- Visual comparisons paired with readable values or labels.

## Avoid

- Prose as the sole representation of relationships that can be shown clearly.
- Decorative visual encodings whose meaning users must guess.

## Use when

- Designing plugin surfaces that explain relationships, comparisons, or structure.

## Do not use when

- A simple label or value already communicates the entire fact.

## Exceptions

- Use text where a visual representation would obscure precision or meaning.

## Evidence

- Requested very visual plugin surfaces because they learn visually, including pitch formations and player comparison cards.

## Check

- Does the visual representation communicate useful structure or comparison?
- Can the user understand its meaning without a separate prose explanation?
