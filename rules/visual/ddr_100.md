# Keep inline document controls in one compact header

Consolidate inline document controls in a single compact header, following the existing inline visualization header treatment.

## Why

Multiple headers and footer controls compete with the document in a conversational surface.

## Prefer

- One compact header using established inline artifact styling.

## Avoid

- A second header or a separate footer for document controls.

## Use when

- Arranging controls around an inline document in a bb conversation.

## Do not use when

- Full workspace editors requiring a larger toolset.

## Evidence

- During inline document design, the user requested one compact header, removed footer controls, and matched the inline visualization header.

## Check

- Are document controls consolidated in one header?
- Does the header match the surrounding inline artifact style?
