# Keep disclosure rows below results in the visual hierarchy

In thread result lists, More and Show more controls should remain recognizable as actions while receiving less visual emphasis than the content users are choosing and remaining distinct from section headings.

## Why

A utility for expanding a list should not become its strongest visual element or be mistaken for a section label.

## Prefer

- Result content as the main focus, with restrained disclosure controls.
- Clear visual separation between disclosure rows and section or project headings.

## Avoid

- Show more becoming the most prominent element among thread titles, metadata, and section headings.
- Styling disclosure actions so similarly to headings that their different roles become unclear.

## Use when

- Styling More or Show more rows in grouped thread lists.

## Do not use when

- Designing an empty state where a single action is intentionally the primary task.

## Exceptions

- Focus and hover may strengthen the disclosure affordance while preserving its role.

## Evidence

- In a palette hierarchy pass, the user objected that Show more resembled labels and drew more attention than titles and metadata, then requested the same hierarchy consideration for sidebar More rows.

## Check

- Does attention go to the thread content before the disclosure action?
- Can users distinguish a disclosure row from the adjacent heading?
