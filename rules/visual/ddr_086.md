# Use named columns for section settings

In Thread Organizer settings, separate the section name, routing rule, and entry prompt into clearly named fields, retaining columns on desktop and using the product term Section.

## Why

Different kinds of editable text need a visible structure so users can distinguish naming, routing, and messages sent on entry.

## Prefer

- Separate named fields for Section, Rule, and Entry prompt.
- Desktop columns that keep the fields aligned across sections.
- Section terminology matching the sidebar.

## Avoid

- Blending routing rules and entry prompts into an undifferentiated text block.
- Calling sidebar sections stages in the settings interface.

## Use when

- Designing or revising Thread Organizer section settings.

## Do not use when

- Choosing layouts for unrelated forms or defining internal data names.

## Evidence

- In one settings redesign, the user called the design confusing, requested multiple named fields and columns, and replaced stage with section.

## Check

- Are section names, routing rules, and entry prompts separately named?
- Does desktop retain aligned columns?
- Does the interface call these objects sections?
