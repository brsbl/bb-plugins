# Show the proposed design before asking for a decision

A proposal that asks the user to choose must render the proposed interface — sketches, mockups, or real component stories — for each option and each major screen; a written description of a layout is not a decidable artifact.

## Why

Prose alternatives cannot be compared, so a decision requested without a rendered artifact either stalls or is made on the wrong information and reworked later.

## Prefer

- Render each option and each major screen or flow before requesting a choice.
- Build the mock from the product's real components so the rendered states are reachable.
- Keep the options inline with the feature they affect and editable where the decision is recorded.

## Avoid

- Describing layout alternatives in prose and asking which one to build.
- A detached decision matrix separated from the feature it decides.
- Beginning implementation before the visual direction is approved.

## Use when

- A proposal, plan, or specification asks the user to choose between interface directions.
- Substantial user-visible UI work is about to begin.

## Do not use when

- The decision is not about a user-visible surface.
- The user has already approved the direction and only implementation detail remains.

## Exceptions

- **A rendered mock cannot yet be produced.** Say what blocks it and propose the smallest artifact that still makes the choice decidable, rather than substituting prose.

## Evidence

- Required plans and specifications to include mockups of every new screen and major flow, not descriptions.
- Halted implementation and asked for reviewable proposals and shared components before anything was built.
- Said written option descriptions meant nothing and asked for a rendered mockup of each option and state.
- Rejected a detached decision matrix and required options inline per feature with sketches beside the prose.
- Required a specification to embed one interactive mock per component, built from real product components.
- Required a specification proposing an interface to carry renderable prototypes and simple flow diagrams.

## Check

- Does every option the user is asked to choose between have a rendered artifact?
- Is the mock built from real components and reachable states?
- Is the decision recorded where the user can still edit it?
