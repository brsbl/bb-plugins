# Keep visual evidence inline

Render screenshots in the message where the claim is made; a file path or link may supplement the image but never stands in for it.

## Why

Evidence behind a link is evidence the reader has to go fetch, so in practice the claim gets accepted unseen and the screenshot stops functioning as proof.

## Prefer

- Show the image inline, next to the statement it supports.
- Add a durable file link alongside the image for anyone who needs the full artifact.
- Show the current capture, taken after the last change that could affect it.

## Avoid

- A list of file paths presented as visual evidence.
- Linking the screenshot and describing what it shows instead of showing it.

## Use when

- A report claims a visual outcome, or asks the user to judge one.

## Do not use when

- The artifact is not visual, or the user asked only for the durable record rather than a readable report.

## Evidence

- Visual QA guidance requires the final screenshot inline in the user-facing report, with links supplementing rather than replacing it.
- Standing guidance requires screenshot evidence rendered inline in chat rather than hidden behind file links.

## Check

- Is every visual claim accompanied by the image itself?
- Was the capture taken after the most recent relevant change?
- Is a link doing the job the image should be doing?
