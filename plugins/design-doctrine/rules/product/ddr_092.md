# Collapse overlapping coordination concepts

When two agent roles describe the same coordination responsibility, prefer one relationship model and vocabulary that remain understandable through nested threads.

## Why

Overlapping coordinator roles make users learn multiple concepts for the same responsibility, especially when a thread both delegates and belongs beneath another thread.

## Prefer

- Use an existing parenting relationship when it already expresses coordination.
- Use relationship language that makes sense for intermediate threads as well as roots and leaves.

## Avoid

- Introducing a separate coordinator concept solely to rename an existing parent role.

## Use when

- Introducing agent roles or revising the thread hierarchy and its terminology.

## Do not use when

- Roles represent distinct responsibilities that users need to control independently.

## Evidence

- During a Workspace exploration, the user challenged separating the coordinator from parenting and explicitly asked to collapse concepts for a simpler mental model.

## Check

- Does each proposed role express a distinct user-relevant responsibility?
- Can the same relationship model explain a thread that both has a parent and owns sub-threads?
