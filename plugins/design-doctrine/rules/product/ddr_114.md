# Avoid features that depend on manual upkeep

Do not propose product features whose value depends on users manually creating, linking, and maintaining records; capture the needed information automatically from work that already happens, or drop the feature.

## Why

Users will not maintain curated records, so features that rely on manual upkeep go stale and deliver no value.

## Prefer

- Deriving records automatically from threads, artifacts, and decisions already being made
- Explaining concretely how a feature stays useful with zero maintenance

## Avoid

- Registries, decision logs, or record systems that require manual creation, linking, pinning, or archiving to stay useful

## Use when

- knowledge features
- decision logs

## Do not use when

- user wants curation

## Exceptions

- Lightweight explicit actions that are optional and the feature still works without them

## Evidence

- User rejected a proposed design-record plugin MVP: no one would maintain it, so its usefulness was unclear.

## Check

- Does the feature still deliver value if no one ever manually edits or curates it?
