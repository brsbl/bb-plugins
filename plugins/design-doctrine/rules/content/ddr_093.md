# Selection tooltips should help people recognize the target

A captured-selection pill's tooltip should add a concise, human-readable description of the selected target, derived consistently from available context rather than repeating the pill label or exposing agent-oriented metadata.

## Why

Users need to recognize what they selected before opening the viewer; repeated labels and technical capture details do not help them confirm the target.

## Prefer

- A short description that adds identifying context beyond the visible pill label.
- Stable descriptive field priorities and useful missing-data fallbacks.
- Language meaningful to the person who selected the element.

## Avoid

- Tooltips that repeat the pill label.
- Generic capture-status copy.
- Agent-oriented metadata presented as the human preview.

## Use when

- Writing preview tooltips for captured UI selections in BB.

## Do not use when

- Displaying technical details in a deliberately technical inspector.
- Writing action tooltips whose purpose is to name a command or shortcut.

## Exceptions

- Technical identifiers may be included when needed to distinguish otherwise identical targets.

## Evidence

- The user rejected selection tooltips as agent-oriented and repetitive, then requested consistent descriptions derived from existing element information.

## Check

- Does the tooltip help a person identify the selected target?
- Does it add useful information beyond the pill label?
- Does identical context produce the same description, with a useful fallback when details are missing?
