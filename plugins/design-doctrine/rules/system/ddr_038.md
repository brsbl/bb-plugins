# Normalize peer control clusters

Treat a row or cluster of peer controls as one small system: one shared gap token between adjacent items, shared control-box and glyph-size tokens, and spacing measured between visible edges.

## Why

Individually tuned controls drift apart as labels, states, and membership change, and the resulting unevenness reads as carelessness even when each control is correct on its own.

## Prefer

- Use one semantic gap token across the cluster, including matching clusters on opposite sides of a surface.
- Measure spacing from visible boundaries; a selected or active background fill is the boundary, not the text.
- Give peer icon buttons shared control-box and glyph-size tokens so targets and glyphs read as equal.
- Define any optical exception at the shared component or token level, with the reason recorded.

## Avoid

- Local margins and per-icon size overrides that only fix one instance.
- Spacing that changes when an item becomes selected or its label grows.
- Equivalent left and right clusters using different gap values.

## Use when

- Two or more peer controls sit together in a header, toolbar, or action row.

## Do not use when

- The controls are not peers, such as a primary action deliberately separated from secondary ones, where the difference is the point.

## Evidence

- Standing design guidance requires peer control clusters to share gap and size tokens and to be measured from visible edges.
- Critique guidance verifies uniform visible-edge gaps, shared glyph tokens, and the absence of local overrides.

## Check

- Does one gap token govern the whole cluster, including its mirror on the other side?
- Do selected and unselected items keep the same visible spacing?
- Is any spacing or size value set locally rather than by the shared component?
