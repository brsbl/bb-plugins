# Make agent inputs and outputs inspectable

When an agent acts, the user should be able to see what it was given, what it produced, and what it did — without leaving the surface or reading a log.

## Why

Trust in an agent comes from being able to check its work, so hidden context and unreviewable output push the user into either blind acceptance or blanket distrust.

## Prefer

- Show the context the agent actually received, in the form the user recognizes.
- Make output inspectable in place, and keep a history of what was done.
- Communicate uncertainty where it changes what the user should do next.

## Avoid

- Context that is assembled invisibly and cannot be reviewed.
- Results the user can accept or reject but not examine.
- Presenting an inferred result with the same confidence as a certain one.

## Use when

- An agent consumes user context or produces a result the user is expected to act on.

## Do not use when

- The step is a routine mechanical operation with no judgment, where exposing its internals is noise rather than transparency.

## Evidence

- Critique guidance requires agent inputs and context to be visible, outputs inspectable, history available, and the user in control.

## Check

- Can the user see exactly what the agent was given?
- Can they examine the result rather than only accept or reject it?
- Is uncertainty visible where it should change the user's next move?
