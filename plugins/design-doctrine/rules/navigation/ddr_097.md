# New threads start in a neutral section

In bb, new threads should appear in the native Threads section until explicitly assigned a workflow stage.

## Why

A workflow section communicates the stage of work. Automatically placing a new thread in Review gives it a status it has not earned.

## Prefer

- Keep newly created, unassigned threads in the native Threads section.
- Make workflow placement reflect an explicit stage assignment.

## Avoid

- Using the first displayed workflow section as the implicit stage for every new thread.

## Use when

- Designing initial thread placement in bb with Thread Organizer enabled.

## Do not use when

- Defining code-review procedures or instructions for agents.
- Routing threads that already have an explicit stage assignment.

## Evidence

- The user objected to new threads appearing in Review and asked for them to stay in Threads until moved.

## Check

- With Review displayed first, does a newly created unassigned thread still appear in Threads?
- Does an explicit stage assignment move the thread to the selected section?
