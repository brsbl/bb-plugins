# One clear next step per screen; top two paths prominent, the rest tertiary

Each onboarding or guidance screen leads to one clear next action, with copy focused on it and the key asset scaled up. It should feel like the only next step while staying contextual and helpful, not annoying. When the user must choose, show the top two ways users actually complete the step as prominent paths. Put everything else needed to avoid dead ends at tertiary, metadata level, or behind a small overflow.

## Why

A single obvious path moves new users forward without making them triage. Covering the two most common completions serves most users, and keeping the long tail at metadata level avoids dead ends without adding noise.

## Prefer

- One primary next action per screen, with copy trimmed to support it
- Larger key assets (task rows, buttons, previews) for the next action
- For choices, the two most common completion paths as prominent options, ranked by usage data
- Other options as a tiny overflow or tertiary metadata-level link
- New pages that keep the button layout of existing pages

## Avoid

- Several equally weighted actions on one screen
- Listing every provider or option at the same prominence
- Hiding the long tail so completely that some users hit a dead end
- Guidance that feels pushy or interrupts instead of fitting the moment

## Use when

- Designing setup, onboarding, or first-run screens
- A screen asks the user to pick among several ways to complete a step
- Adding in-product guidance or hints

## Do not use when

- Settings or reference pages where users browse every option deliberately

## Evidence

- Reviewing the guidance v2 walkthrough, the user asked for one clear next action per screen, two prominent paths for choices, the rest tertiary, providers trimmed to two plus an overflow, and button layouts kept consistent.

## Check

- Can you name the single next action on this screen within 2 seconds?
- Are there at most two prominent choice paths, chosen from usage data?
- Is every remaining option reachable from a tertiary link or overflow?
- Do the buttons match the placement and order on existing pages?
