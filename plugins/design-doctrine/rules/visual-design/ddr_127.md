# Use the same icon for the same feature across surfaces

When a feature appears in multiple places (an inline trigger and a persistent control), use one icon for it everywhere so users recognize it as the same thing.

## Why

Consistent iconography ties the entry point to its ongoing state and avoids users wondering whether two controls are related.

## Prefer

- Reusing the inline trigger's icon in the status/footer control

## Avoid

- Different glyphs or a text label for the same feature in different surfaces

## Use when

- A feature has an entry point and a separate status or control surface.

## Do not use when

- The two surfaces represent distinct actions that need distinct affordances (e.g. play vs pause state).

## Exceptions

- State icons (play/pause) may change to reflect current state.

## Evidence

- User asked that the footer control use the same icon as the read-aloud button under agent messages, and that the control show a pause icon when paused.

## Check

- Does every surface for this feature use the same base icon?
- Does the control's icon reflect current state?
