# Editorial typography for data-viz overlays

Text overlaid on data visualizations should have a clear editorial hierarchy (title, primary value, secondary metadata beneath it), use deliberate type choices that don't look AI-generated, stay legible over the visual, and avoid chunky pills or background chips.

## Why

Generic font choices and pill-backed labels look clunky and AI-made; a newsroom-style hierarchy (e.g. NYT video essays) reads as crafted and keeps text readable.

## Prefer

- one display face for the headline, a clean sans (Geist/Inter) for subtitles, mono for small metadata
- secondary metadata placed directly beneath the value it describes
- subtitle sized smaller than the hero value
- legible contrast against the map without boxes

## Avoid

- pill or background chips behind overlay labels
- flat or confused type hierarchy
- default 'AI-looking' font pairings
- text that is hard to read over the visualization

## Use when

- adding titles, labels, or captions to data-viz images or videos

## Evidence

- User repeatedly rejected overlay text as AI-looking, chunky and hard to read, asking for NYT-style hierarchy with sans and mono roles and no pills.

## Check

- Is there a clear title > value > metadata hierarchy?
- Are pills/backgrounds absent from labels?
- Is every overlay label readable over the busiest frame?
