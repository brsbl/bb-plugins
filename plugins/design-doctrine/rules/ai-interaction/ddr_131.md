# Brief actions go where the task gets done, not just "Read"

Every action button on a brief or digest card should take the user to the place where they finish the task, such as the payment dashboard, the registration page or the ticket page. Name the button for that task. A generic "Read" button that only reopens the source email isn't enough. Keep the source email as a secondary button.

## Why

A button that only reopens the email adds a click without moving the task forward. The user called "Read"-only actions useless.

## Prefer

- Primary button opens the destination page (e.g. 'Review expense in Mercury', 'Register for reunion', 'Get tickets'), with a task-specific label
- Source email as the secondary button
- Capture destination hrefs while reading the email body, without following them

## Avoid

- A generic 'Read' or 'Open' button as the only action
- Linking to URLs that perform a write when opened (one-click confirm/unsubscribe links)

## Use when

- A brief, digest, or summary card offers an action button for an item that needs the user to do something

## Do not use when

- The item is purely informational, with nothing to do beyond reading

## Evidence

- After an unread-email brief where every action button said 'Read' and opened the source email, the user rejected read-only actions and called them useless.

## Check

- Does each needs-you item's primary button take the user to where the task is completed?
- Is the button label a task-specific verb phrase rather than 'Read'?
