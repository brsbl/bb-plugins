# Status tables are scannable at a glance and every ask is actionable

A status or review table built for one person to unblock work must scan at a glance. Use cell borders and strong section hierarchy, show each stage as a visual marker (an icon or mark plus a word), make Next a simple status rather than free text, repeat the column header row in each section, and link every item that needs the reviewer to the thing they act on.

## Why

A plain, low-contrast table with free-text cells blends together. The reviewer can't see what is where or act on what needs them, which blocks the work the page exists to unblock.

## Prefer

- Visible table borders
- Clear hierarchy between section, group and row
- Stage shown as an icon or mark plus a word
- Next as a short status (who or what it waits on)
- Column header row repeated under each section
- Every needs-you item links to the thing to act on
- Work worded simply, value first

## Avoid

- Bland, borderless rows that blend together
- Free-text Next cells
- Needs-you items with no link
- Labels that repeat the goal (for example a unit that restates it)
- Applying marketing restraint rules (one accent, no markers) to a working status surface

## Use when

- Designing or restyling any status, queue or review table someone uses to decide or unblock work

## Evidence

- The user rejected a minimal restyle of the org status table: they want borders, hierarchy, visual stage markers, status-style Next, per-section headers and actionable links.

## Check

- Can the reviewer find each section and stage in a 5-second scan?
- Does every item that needs the reviewer link to an action?
- Is Next a short status rather than a sentence?
- Do column headers repeat per section?
