# Use opaque BB previews with fades at scroll boundaries

BB mention previews and inspectors should match the app's component styling and themes, with opaque surfaces and fades confined to boundaries that indicate scrollable overflow.

## Why

A scroll cue should communicate hidden content while preserving readable, visually consistent preview surfaces.

## Prefer

- The same component styling and theme treatment as the rest of BB.
- Opaque preview backgrounds.
- Boundary fades that signal additional scrollable content.

## Avoid

- Translucent backgrounds used as a substitute for a scroll fade.
- Bespoke preview styling that does not follow BB themes.

## Use when

- Designing BB mention tooltips or context inspectors with overflowing content.

## Do not use when

- Designing ambient backgrounds or decorative transparency outside preview surfaces.

## Exceptions

- Follow a different surface treatment when the user explicitly requests it for the current design.

## Evidence

- The user rejected translucent mention previews, clarified that fades indicate scrolling, and asked for BB component styling that follows themes.

## Check

- Does the preview use an opaque background consistent with BB's themed components?
- Do fades appear at overflow boundaries rather than reducing opacity across the surface?
- Does changing the BB theme update the preview styling?
