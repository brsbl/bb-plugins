# Choose readable, distinct resource icons and reuse them consistently

For bb resource navigation, prefer icons that remain readable at sidebar size, convey the resource's meaning, and distinguish it from other concepts; use the same resource icon in the sidebar and creation menu.

## Why

An icon can be simple yet too abstract, or readable yet misleading when it already identifies another concept.

## Prefer

- Readable silhouettes with a recognizable connection to the resource.
- Consistent icons for the same resource across sidebar and creation menu.

## Avoid

- Detailed resource icons that are hard to read at navigation size.
- Reusing a queueing symbol for automations when it obscures their distinct meaning.
- Abstract substitutes chosen solely for simplicity.

## Use when

- Selecting or changing icons for bb resource navigation and creation actions.

## Do not use when

- Choosing decorative artwork or icons outside resource navigation.

## Evidence

- Rejected hard-to-read resource icons, questioned an abstract grid, rejected the queueing clock for automations, and requested matching creation-menu icons.

## Check

- Is the icon readable at its actual rendered navigation size?
- Does its meaning fit the resource without colliding with another concept?
- Does the same resource use the same icon in the sidebar and creation menu?
