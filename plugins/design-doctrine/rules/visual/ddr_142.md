# No tertiary explainer text

Dashboards, mockups and UI show only the content itself. Do not add tertiary explainer text: subtitles restating the title, status pills or badges, 'updated … refreshes daily' stamps, 'N of M' counts, captions or footnote lines explaining the data.

## Why

Extra explanatory text competes with the one thing the screen exists to show; the owner has ADHD and reads visually, so every extra line dilutes the answer.

## Prefer

- One row per item with its name, its state and its value
- Facts that matter expressed as the content (e.g. the state word) rather than a note about it

## Avoid

- Subtitle questions under titles
- Sample-data or status pills
- Updated/refreshes timestamps
- N of M launched counts
- Captions explaining chart axes or methods
- Footnote lines under charts

## Use when

- Designing or reviewing any dashboard, mockup or UI for brsbl

## Evidence

- Owner rejected a dashboard mockup for its explanatory text, pills, timestamps and counts; wants only how each experiment is doing.

## Check

- Every text line on screen is a name, a state, or a value
- No line exists only to explain another element
