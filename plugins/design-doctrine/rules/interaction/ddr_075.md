# Preserve notification retry beneath temporary errors

When opening a bb mobile notification fails, overlay temporary error feedback on the original notification, then clear the error so the original action remains available for retry.

## Why

Failure feedback should explain the failed action while preserving the user's way to try again.

## Prefer

- Temporary error feedback over the original notification.
- Returning to the original notification's retry action after the error clears.

## Avoid

- Replacing or expiring the original notification before the user can retry.

## Use when

- Designing failure feedback for a bb mobile notification's Open action.

## Do not use when

- Errors without a retryable notification action or operating-system notifications.

## Evidence

- In a notification retry episode, the user requested an error overlay that dismisses after a delay so the original notification can be used to retry.

## Check

- Does the error overlay the original notification?
- After the error clears, can the user retry from the original notification?
