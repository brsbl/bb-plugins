# Preserve plugin detail context during collection navigation

Within bb Extensions, navigation between Browse and author collections should update the collection pane while preserving open plugin detail tabs, their order, and the active tab. Plugin uninstall should not navigate the user to another collection.

## Why

Users should keep their comparison context and place in the workspace while browsing or managing a plugin.

## Prefer

- Update only the region whose content changes.
- Preserve detail-tab contents, order, and active state through author navigation and return to Browse.
- Render detail loading incrementally within the existing page context.

## Avoid

- Closing detail tabs when following an author link or returning to Browse.
- Blank or full-page remount flashes during local navigation.
- Redirecting to My Plugins after uninstall.

## Use when

- Implementing Browse-to-author navigation, return navigation, plugin detail loading, or uninstall completion in Extensions.

## Do not use when

- The user explicitly closes a tab or deliberately leaves the Extensions workspace.

## Exceptions

- An uninstalled plugin may need its own detail content updated to reflect its new state; that does not require navigating the collection.

## Evidence

- During Extensions iteration, requested persistent detail tabs across author navigation and flagged tab loss and uninstall redirects as bugs.

## Check

- Do open tabs retain their order, content, and active state across Browse-to-author-to-Browse navigation?
- Does the surrounding interface remain visible during loading?
- Does uninstall leave the user in the same collection context?
