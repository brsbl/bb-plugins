# Reserve document diffs for pending agent proposals

In collaborative document editing, allow direct click-to-edit and show a live diff only while an agent proposal awaits acceptance or rejection; ordinary user editing should not show a diff.

## Why

The diff communicates an unresolved agent proposal rather than a separate editing mode.

## Prefer

- Direct editing in the document.
- Live proposal diffs until acceptance or rejection.

## Avoid

- Separate Edit/Diff toggles.
- Diff decoration during ordinary user edits.

## Use when

- Designing document editing with agent-proposed revisions.

## Do not use when

- Dedicated version-history comparison or code-review tools.

## Evidence

- During document-editor design, the user removed the edit/diff toggle and limited diffs to unresolved agent proposals.

## Check

- Can the user click directly into the document to edit?
- Does ordinary editing remain free of diff decoration?
- Does resolving a proposal remove the pending diff?
