# Act on clear intent instead of dead ends

When a user clicks something that needs a disabled or missing dependency, enable it automatically if disabled, or open the install flow if missing, then continue to the destination.

## Why

The click already shows intent; an 'unavailable' page is a dead end.

## Prefer

- Enable-and-open for disabled features
- Install modal then open for missing ones; cancel stays put

## Avoid

- 'This panel is not available' dead-end pages

## Use when

- A navigation target depends on an optional component

## Do not use when

- Enabling or installing has security or cost implications that need explicit consent beyond the install modal

## Evidence

- User asked that clicking a disabled guide enable it and a missing one trigger the install modal.

## Check

- Clicking the entry point never lands on an unavailable state
