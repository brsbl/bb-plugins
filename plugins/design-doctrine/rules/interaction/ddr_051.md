# Name Figma sync commands by their direction

For Moss Figma↔code synchronization, prefer short commands that name the source and destination explicitly, such as figma-to-code and code-to-figma.

## Why

Explicit direction makes the operation understandable without remembering what pull or push means relative to the current tool.

## Prefer

- Short source-to-destination names for the two sync directions.

## Avoid

- Pull/push labels that require explaining which system changes.
- Extra command prefixes that add length without clarifying the direction.

## Use when

- Naming user-facing commands for Moss Figma↔code synchronization.

## Do not use when

- Naming unrelated commands or established third-party interfaces.

## Exceptions

- Preserve compatibility for existing command consumers when changing names.

## Evidence

- Asked which direction pull and push meant, requested more intuitive commands, then explicitly shortened them to figma-to-code and code-to-figma.

## Check

- Can the user tell the source and destination from the command alone?
- Is the name concise without losing direction?
